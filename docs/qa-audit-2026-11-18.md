## 3. Defects found and fixed

1. **Brand logo was invisible in the sidebar.** Defaults pointed at
   `/brand/zoolyum-logo.svg`, a file that did not exist (only the `-dark` /
   `-light` variants were shipped), so the dark-text artwork landed on the dark
   rail. Replaced with the supplied white/black artwork, correct path mapping
   and a proper 512×512 `icon.png`.
2. **A new client silently lost its credit limit / credit hold / score
   profile.** `CreateClientBody` accepted them, `create()` never wrote them
   (`update()` did). `apps/api/src/accounts/accounts.service.ts`.
3. **A role created with legacy module keys lost permissions.** `CLIENTS`,
   `LEADS`, `PROJECTS`, `FINANCE`, `INSIGHTS` were only migrated for *existing*
   roles, so a create with `CLIENTS` stored nothing. Now migrated on input too.
4. **Enrollment update returned a misleading 404.** The service accepted
   `score` / `certificateUrl`, which are not columns, Prisma threw, and the
   catch converted every error into "Enrollment not found". Fields restricted
   to real columns and P2025 is now the only 404.
5. **Two buttons named “Add Account”** on Capital → Accounts (chart of accounts
   and bank accounts). The bank one is now “Add bank account” (also fixes the
   ambiguous e2e locator).
6. **Dark mode kept the white-safe (dark) brand orange.** The branding provider
   wrote `--primary` inline on `:root`, which beats the `.dark` rule. Primary is
   now theme-scoped (`--brand-primary-light` / `--brand-primary-dark`) and
   `--primary-strong` keeps white-text pills legible in both themes.
7. **55 WCAG contrast violations** (status chips, muted hints, brand chips).
   Light-mode AA overrides for the 400/500 chip shades, theme-aware tier chips
   and a brand colour that clears AA on white *and* on its own 10% tint bring
   axe-core to **0 violations** on 12 pages in both themes.

## 4. Brand system applied

* Palette from the logo: orange `#FF5001`, black `#0B0A09`, white (plus amber
  `#FF8A2B` as the secondary accent).
* Light: warm off-white surfaces, near-black ink, deep-orange actions
  (`#C43D01`, AA with white text), orange accents; dark: near-black surfaces,
  bright orange (`#FF6A2B`) with dark text on buttons, exactly like the logo.
* Sidebar stays black with an orange active pill (white text, 4.7:1).
* Logo: white wordmark on dark chrome (sidebar, dark theme, portal login dark),
  black wordmark on light chrome (login, landing, invoices/PDF).
* Chart palette anchored on orange → amber → sky → emerald → rose.
* Docs updated: `docs/design-system.md`, `README.md`.

## 5. Not verifiable in this environment

* WhatsApp / Telegram real delivery — no bot token or gateway configured; both
  are validated in mock/graceful-degrade mode (tests assert the degrade path).
* Google / Meta ad sync — no production credentials; the datasource round-trip
  and sync endpoint are exercised against stored test credentials.
* SMTP — the email sender is a stub in this build; “test send” only logs.
* Payment gateway flows — none configured; invoice payment recording is tested.
* Large binary uploads — signed-URL, metadata and approval flows are covered;
  big-file transfer was not stress-tested.
